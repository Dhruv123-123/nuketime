# D10: CONCLAVE, a compound AI exploration lab

Date: 24 Oct 2026. Architect: D10 agent. Builds on `../../model/MODEL.md` (SENTINEL-COX), `../../MEMO.md` and evidence files L01-L40. No new web searches were run. Numbers come from the L-files, which cite primary sources. My own arithmetic and unchecked items are marked (unverified).

## 1. Name and summary

**CONCLAVE** is a lab, not a single model. It runs about ten specialist "expert" models side by side. Each expert sees the same evidence ledger and emits a full predictive distribution for the same small set of target events. A **hierarchical Bayesian stacking layer** learns, per cell, how much to trust each expert. Weights depend on province, archetype, data density and distance from labels. Above the experts sits an **agent layer**. Agents propose hypotheses, new features, new archetypes, data pulls and sensor jobs. They can never change a score directly. Every proposal becomes a typed object that must win a held-out log-likelihood test before it enters production. A **decision layer** (portfolio POMDP over buy, drop, sense, drill, sell) turns the stacked posterior into a ranked buy list and a field schedule. The whole thing is also the company operating system: land, field crews, data rooms and sales all read and write one bitemporal ledger, and every forecast is hashed before outcomes arrive. SENTINEL-COX is kept as the "integrator" expert and the default when stacking has too little data to move. The bet is simple: in geothermal the algorithm barely matters (L04), but no single model is right everywhere. A lab that keeps many honest models, measures each on dated hindcasts and learns where each one works should beat any single model, including Zanskar's LightGBM.

## 2. Target variables and decision output

Every expert must predict the same **observable contract**. This is what makes them stackable.

| Target | Definition | Scale |
|---|---|---|
| Y1 existence | A system of 120 C or more within 2 km of the cell centre | 500 m cell, EPSG:5070 equal-area |
| Y2 temperature | T at 0.5, 1, 1.5, 2, 3 and 4 km, as 128 ordinal bins (ICE style, L10) | Same cell |
| Y3 failure ladder | Competing-risks class of a hypothetical 800 m hole: no heat / hot but tight / outflow only / masked / fossil / success (L40) | Same cell |
| Y4 well outcome | For any real hole: censored T(z) curve | Point, with location box |
| Y5 size mark | MWe if exists, P10/P50/P90, with a 0.5-0.7x lookback haircut (L17) | System |
| Y6 EGS head | P(200 C at 4 km TVD or shallower) and isotherm depths (L30) | Cell |

**Decision output:** RNPV per acre for each PLSS 40-acre aliquot and each legal parcel, using the fixed GETEM-style layer from MODEL.md (`evidence/M34_econ.py`). Plus: the gap to the **crowd posterior** (Section 4, E10), a reservation value per parcel, and a ranked action list (lock, nominate, option, probe, MT, TG hole, drop) with EVSI per dollar. The buy list is released with a conformal-selection false discovery bound (L27).

## 4. Components and methods

### 4.1 The Ledger (company memory)

A typed geothermal knowledge graph (L23) stored as GeoParquet tables plus Zarr cubes in one bucket, queried by DuckDB (L35). Node types: system, well, measurement, document, fault segment, parcel, lease case, bid, sensor deployment, forecast, outcome. Every value carries `valid_time`, `known_time`, source, extraction model, prompt hash, confidence, location box and search channel. Hindcasts use point-in-time joins on `known_time`, so a 1990 freeze sees only what was public in 1990 (L19). Cold wells, dry holes and "temperature absent" driller reports are first-class nodes, not missing rows.

### 4.2 The expert bench

Each expert is a separate, versioned code package with one interface: `predict(cell_or_point, freeze_date) -> distributions over Y1-Y6, ood_score`. Experts that cannot predict a target return "abstain", and stacking handles that natively.

- **E1 SENTINEL-COX integrator.** The existing design: log-Gaussian Cox count thinned by dated search effort, per-source censored 1D column likelihoods, shared latent mask class, now split into the categorical archetype B1-B7 (L09). Fitted with INLA or variational Laplace on the 500 m lattice. It is the default expert and the prior centre of the stacking weights.
- **E2 Layer GBM.** LightGBM on the USGS 53-feature release (doi 10.5066/P14QM39R) plus INGENIOUS layers, detrended (L03), with PU learning, isotonic calibration and an area-of-applicability mask (Saduov 2026 recipe, L04). Labels frozen at each freeze date. This is the "Zanskar-class" expert and a baseline we must beat.
- **E3 In-context temperature transformer.** Initialised from LANL In-Context Earth (arXiv 2605.16665, 4.7 C US MAE). Tokens are raw readings: BHT, shut-in time, era, extraction sigma, location error. Conductive mean from Burns 2024 or Stanford InterPIGNN; convective residual governed by a flow-regime latent (L10, L29).
- **E4 Physics SBI.** A 3D Basin-and-Range FNO surrogate trained on 5,000-20,000 TOUGH3/Waiwera runs across Faulds setting types, dips, heat flux and aquifer sweep (L11, L12). An amortised NPE ensemble maps each cell's observations to posteriors over upflow existence, offset and T(z). An MMD misspecification test flags cells off the simulator (L28).
- **E5 Chemistry SBI.** A forward mixing model (reservoir T, hot fraction, cold end-member, CO2 loss) run millions of times in PHREEQC; an NPE gives per-sample posteriors. Helium R/Ra enters as a permeability channel only. Anomalies are back-projected up the NWIS head gradient (L26).
- **E6 Structure-permeability.** A U-Net FSS mapper trained on the 1,430 Faulds polygons, run on 3DEP lidar, GeoDAWN magnetics and gravity (L02, L04). A Monte Carlo stress model from ML focal mechanisms gives P(critically stressed) per segment (L25). A sealing clock decays openness with time since last slip (L40). A GNN passes messages along the fault graph (L16, L29).
- **E7 Geophysics ensemble.** MT and gravity enter as 50-200 posterior models from randomize-then-optimize or trans-D inversion (L13). A learned resistivity-to-temperature link with false-conductor classes (basin clay, brine, fossil cap). Variance grows below the deepest calibration well.
- **E8 Surface detector.** EMIT/AVIRIS sub-pixel alteration, a persistent LST residual from a learned expected-LST model, NISAR and Sentinel-1 strain, and 8-16 AlphaEarth embedding components (L20, L24). It predicts detection, so it mostly informs the effort and mask terms. A fossil-versus-live latent penalises alteration with no live signal.
- **E9 Analogue retriever.** Graph and AlphaEarth embeddings find the nearest proven systems (Blue Mountain, McGinness Hills, Big Blind, Pumpernickel). It predicts Y1 and Y5 by weighted analogy. It is weak alone but useful where data are thin.
- **E10 Crowd posterior.** The same E2 recipe trained only on what rivals can see: INGENIOUS, USGS favourability, public discoveries, BLM nominations and bid history (L37). It is never stacked into our geology posterior. It is a separate output used to compute the edge: our RNPV minus the crowd-implied price.

### 4.3 Stacking and model averaging

Plain BMA is wrong here because no expert is the true model, so BMA collapses onto one. We use **hierarchical stacking** (Yao, Vehtari, Gelman and co-authors, 2018 and 2022): weights are a softmax of a linear function of cell descriptors z(x). Descriptors are province, the E1 archetype posterior, the area-of-applicability index, distance to nearest label, and which data modalities are present. Weights are fitted by maximising the **held-out log predictive density** of Y2 and Y4 on real wells (thousands of points) and of Y1 on dated discoveries (tens of points). Folds are both kNNDM spatial folds (L19) and walk-forward time splits frozen at 1980, 1990, 2005 and 2015, with 10-20 km purge and a 2-year embargo. A Dirichlet prior shrinks the weights toward E1 when data are thin. A final calibration step per province and mask class uses isotonic regression for Y1 and conformalised quantiles for Y2.

**Double counting rule.** Experts may share raw data. Stacking on held-out predictions handles redundancy, because two experts that say the same thing do not add weight. But we never multiply expert likelihoods together. The only place raw observations are multiplied is inside E1, where each observation is owned by exactly one likelihood term.

**Disagreement as a signal.** Where experts disagree strongly, the stacked distribution is wide and EVSI is high. Disagreement maps become sensor targets, and each disagreement is turned into a cheap test (L23's "contradictions as targets").

### 4.4 Agent layer

Agents run the data plane and the idea pipeline. They cannot edit expert code or weights at run time (L39). They emit typed proposals.

| Agent | Output | Gate before it counts |
|---|---|---|
| Data agents (per-source handbook cards) | New ledger rows with extraction sigma | pass^5 above 95% on a golden suite with planted unit and datum traps; two independent extractors diffed |
| Hypothesis tournament (per basin, co-scientist style) | Archetype, rule, feature or conceptual model | Must raise held-out log score on the hindcast; ranked by that gain, never by LLM Elo (L22) |
| Data-request agent | "Pull dataset X" or "digitise archive Y" | Ranked by expected log-score gain per dollar from E4/E7 imputation |
| Sensor-request agent | Draft field job (2 m array, E-field MT, TG hole, ICP bottle) | Decision layer must find positive EVSI per dollar |
| Physics skeptic | Flags hotspots no convection run can produce | E4 forward check; flagged cells get wider bands |
| Leakage red team | Finds post-discovery features, LLM memorisation, cherry-picked freezes | Must pass before any skill number is published |
| Prior-claimant agent | Lease, nomination and rival status per parcel | Daily MLRS and state lease diffs |
| Watchers | New GDR logs, NDOM permits (Granite Springs 68-02), DOE drilling data | Trigger re-scores and "pending label" holds |

Agents also write dossiers for the top few thousand cells by EVSI, so deal review is fast.

### 4.5 Decision layer

A portfolio POMDP whose state is the stacked belief plus our holdings. Actions are buy, nominate, option, drop, sense, drill and sell. It uses depth-2 to depth-3 look-ahead (Martinelli 2013 gained about 14.8% over myopic) with a Brown-Smith information-relaxation bound to show how much is left on the table (L15). Each parcel has a Pandora reservation value, so the policy knows when to stop measuring and just lock the right. Bids are corrected for the winner's curse using a modelled count of rivals from E10. Each public action carries a leak cost: how far E10 would move if we nominate. High-leak targets go to private ranch heat, state first-file and leftover BLM parcels.

## 6. Labels and negatives

Positives are the dated discovery ledger: the 205-system USGS Great Basin inventory, the 11-case blind ladder (L31), and Zanskar's announced finds, each tagged with first-signal date and channel. Negatives come in four kinds. First, censored columns: every cold or warm well constrains T(z) at its depth only, so a cold 150 m hole does not zero an 800 m reservoir (L02's Argenta case). Second, designed negatives: Reese River's 10 cold TG wells, MSH17-24, the four cool Gabbs holes. Third, graded effort: driller reports that never mention heat lower intensity through the thinning term, scaled by the detection probability of their mask class. Fourth, failure-mode labels: AI extraction of completion reports tags each dry hole as no heat, tight, outflow, masked or fossil (L40). The PU label frequency c(x) is estimated per mask class and tied to the effort term (L19, L27).

## 7. Uncertainty and validation

- Each expert ships an ensemble (10-20 members by spatial-block bootstrap) or a posterior sample. Stacking runs on full predictive distributions, not point scores.
- Stacking weights themselves are uncertain. We sample them from their posterior, so the final band includes "we are not sure which expert is right here".
- Release gates: 85-95% coverage of 90% bands for T(z) on 10 km blocks; PIT KS under 3%; SBC and TARP for the NPE experts; CSEP N, L and S tests for the Cox rates on a 2010 freeze (L27, L36).
- Headline skill: blind-system area-capture (Molchan) at 1%, 5% and 10% of area, Boyce index, and dollars per bankable MW in a replay of BLM lease sales. Always reported beside three baselines: the 1-in-550 base rate, a distance smoother, and E2 alone. Random, kNNDM and time-split scores all shown.
- The key extra test for this design: **stacked versus best single expert**, on the same folds, with bootstrap intervals.
- Pre-registration: every map is hashed and timestamped before each BLM sale, field season and NBMG release.

## 8. Agents and compute at scale

The heavy compute is offline and amortised. FNO training needs about 10^4 TOUGH3 runs; at about 2 minutes per run on 32 cores, this is a few hundred thousand core-hours, roughly $10-30k of cloud (unverified). NPE training on 10^6 simulations takes days on 8 GPUs. Document AI is the largest variable cost: NBMG, NDWR (about 132k reports), CalGEM, NDOM, UT DOGM and OSTI, run five times each for self-ensembles. At a few cents per page this is about $50-150k for the West (unverified). Re-scoring all 12 million West cells across ten experts is cheap once trained: minutes on a GPU node. Agents run continuously as a fleet of perhaps 50-200 concurrent workers on watch, extraction and tournament duties.

## 9. Why it beats Zanskar

1. **More honest labels.** Zanskar's GeoCore used 6,009 warm wells against 148 cold ones (L05). CONCLAVE turns every well, including tens of thousands of shallow cold ones, into a censored column observation.
2. **Knows where each model works.** A GBM is good in data-rich Nevada valleys. Physics SBI is better on deep, unvented B3 targets like Big Blind. Analogue retrieval helps in thin-data states. Learned per-cell weights capture that; one LightGBM cannot.
3. **Effort and crowd modelling.** Zanskar publishes no search-effort term and no model of what rivals know. E10 makes our edge computable and keeps us out of bidding wars.
4. **Faster idea loop.** Agents test hundreds of hypotheses a month against a frozen hindcast. A human team tests a handful.
5. **Rights focus.** Private ranch heat and state land are scored on the same posterior. Zanskar's footprint is mostly federal.
6. **Verifiable track record.** Hashed forecasts plus a Sodir-style lookback become a data-room exhibit buyers trust (L17, L37).

## 10. How it drives rights buying and sensors

Each night the decision layer re-scores every cell and parcel. Parcels where our RNPV/acre beats the crowd price by a set margin, and pass conformal selection at a chosen false-discovery rate (say 30%), go to the land team as lock or option tickets. The ticket says which route: private lease, state first-file, leftover BLM or nomination with decoys. Cells with high value but wide bands go to the sensor queue. The queue is batched per mobilisation with a travel-cost term and determinantal selection (L38). Typical order in Basin-and-Range: 2 m probes and gradient holes first, then E-field MT, then intermediate wells at Zanskar's proven gate of about 750-850 m (L05, L31). Every result returns to the ledger within days, the experts re-score, and stacking weights refit monthly.

## 13. Cheapest first test and pass bar

**Test: does stacking beat the best single expert on a dated hindcast?** Cost about $5-10k and three weeks, using only public data already listed in MODEL.md.

Build four cheap experts: E2 (USGS rebuild), E3-lite (universal kriging on Burns 2024 wells), E1-lite (effort-thinned LGCP, no document AI), and a distance-to-known smoother. Freeze at 2005. Fit hierarchical stacking on folds before 2005 only.

Score on:
- (a) log predictive density of temperature at depth for wells first logged after 2005 (expect hundreds to low thousands of wells; unverified count), on kNNDM folds;
- (b) the rank of post-2005 blind discoveries: Gabbs Valley, Granite Springs, Big Blind, Pumpernickel, plus USGS "probable" systems first logged after 2005.

**Pass bar:** the stacked log score beats the best single expert, with a 95% bootstrap interval that excludes zero. The stacked model must also put at least as many post-2005 blind systems in the top 5% of area as the best single expert. In the same run, at least 1 of 20 agent-proposed features must survive the held-out gate after leakage red-teaming. If stacking does not beat the best single expert, we keep CONCLAVE as an operating system around one model, and the lab layer becomes an idea factory only. That is a downgrade, not a kill.

## 14. Biggest risks

1. **Too few blind positives to fit weights.** Tens of dated blind finds cannot fit rich covariate-dependent weights. Mitigation: fit weights mainly on thousands of well temperatures, shrink toward E1, and use synthetic worlds with planted systems to check weight recovery.
2. **Hidden double counting.** Experts sharing inputs could look independent in-sample. Mitigation: stack only on held-out predictions; one-owner rule for raw data in E1.
3. **Agent errors that pass gates.** Silent datum and unit errors, or hallucinated values. Mitigation: two-extractor diffs, pass^k, physical sanity bands, measured disagreement fed in as noise.
4. **LLM memory leakage in hindcasts.** Agents may "know" that Big Blind exists. Mitigation: red-team memorisation probes; agents propose features, and features are computed from the frozen ledger only.
5. **Complexity and ops burden.** Ten experts plus agents is a lot to keep running. Mitigation: each expert must earn its weight; experts with near-zero weight for two releases are retired.
6. **Deliverability risk outside the model.** Sharp heat posteriors can still sit on tight rock (Cape, Geretsried shortfalls). Keep flow risk as its own wide term in RNPV.
7. **Leak through our own actions.** Nominations and holes inform rivals. Mitigation: leak cost in the POMDP and routing to private and state land.
